# Что брать из FRST, а что нет

Оценка — по опыту корпуса `Parse_FRST_SafeZone/pairs` (1078 отчётов) и по тому,
что реально нужно детекторам GenFix. Приоритет: сначала то, что влияет на
безопасность и качество fixlist, потом «объём», потом отказ от опасного.

## Уже сделано

| Возможность | Как реализовано |
| --- | --- |
| `SigCheck` | Раздел с контрольными системными файлами: подпись (Authenticode + каталоги), размер, даты, MD5; отдельная строка при включённом `testsigning`. |
| `BCD` | `bcdedit /enum all`, только чтение; в GUI — опция скана от администратора. |
| `Ассоциация` | Класс и команда для `.exe/.com/.bat/.cmd/.reg/.scr/.pif/.js/.vbs/.hta/.lnk` в HKLM и профилях; «ВНИМАНИЕ» только при подмене. |
| Карантин и восстановление | `manifest.json` в каждом бэкапе, страница «Карантин», `rusecurity restore` (файлы на место, ветки реестра из `.reg`). |
| Выборочное применение fixlist | Галочки в таблице анализа, сборка fixlist из выбранных строк. |
| Скан от администратора | Опция на странице сканирования: отдельный процесс с UAC и итогом в JSON. |
| ADS в сканере | Обход `%TEMP%`, `Temp`, `Downloads`, `ProgramData` с лимитами по времени и числу файлов; `Zone.Identifier` и служебные потоки отсеиваются. |
| Точки восстановления и журнал | `SystemRestore` + ошибки Application/System за 7 дней (PowerShell, кодировка и время нормализованы). |
| Delta-скан | Снимки в `Reports/history`, сравнение с нормализацией шума, отображение в GUI и CLI. |

## Взять в первую очередь

| Возможность FRST | Зачем | Оценка |
| --- | --- | --- |
| `Файлы в корне каталогов` | Исполняемые файлы в корнях дисков — типичный след adware/майнеров. | 0.5 дня |
| `SvcHost` (белый список) | Группы `svchost.exe` и их DLL: классическое место маскировки. Данные уже есть в реестре (`SvcHostSplitThresholdInKB`, `Parameters\ServiceDll`). | 0.5 дня |
| `Точки восстановления` + `Ошибки журнала событий` | Контекст для эксперта: когда появилась зараза, отключено ли восстановление. | 1 день |
| `Alternate Data Streams` | Уже есть в фиксере, но сканер ADS не собирает — дёшево добавить (обход `::$DATA`). | 0.5 дня |
| `Codecs`, `Association`, `Safe Mode` | Редкие, но дешёвые разделы; полезны против подмены ассоциаций и `SafeBoot`. | 1 день |

## Взять позже, если понадобится

| Возможность | Почему не сейчас |
| --- | --- |
| «Один месяц (создан/изменён)» | Сильный сигнал по датам заражения, но обход всей файловой системы — минуты и мегабайты отчёта. Делать опционально, с фильтрами (только `%TEMP%`, `Downloads`, `ProgramData`). |
| `FCheck` (нулевые байты) | Полезно, но требует открытия каждого файла; дорого и шумно. |
| `FLock` (заблокированные папки) | Нужен для удаления в «боевом» режиме; у нас фиксер и так работает с бэкапами. |
| `KnownDLLs`, `Bamital & volsnap`, `Event[0]` | Узкоспециальные проверки, ценность ниже стоимости поддержки. |
| `Search` (`FindFolder:`, `SearchAll:`, `SearchReg:`) | Это отдельный инструмент поиска, а не сканирование; можно сделать позже как вкладку. |
| Recovery Environment (RE-режим, offline-реестр) | Большой отдельный проект: загрузка в WinRE, монтирование кустов, работа без ОС. |

## Не брать

| Возможность | Причина |
| --- | --- |
| Запись MBR/загрузочного сектора (`SaveMbr:`, `RestoreMbr:`) | Ошибка = незагружаемая система. Читать можно, писать — только вручную и с бэкапом. |
| Автоматический «ремонт» (`sfc`, `ipconfig`, `bitsadmin`, сброс прокси/DNS) | В экспертных fixlist это контекстные действия, а не универсальные правила; переносить в автодействия — шум и риск. |
| Копирование эвристик «ВНИМАНИЕ» | У FRST свои белые списки; мы уже видели ложные срабатывания на легитимных политиках. Лучше меньше меток, но точных. |
| Скрытые загрузки/обновления FRST, телеметрия | У нас портативное приложение без сети. |
| Точное повторение формата (имена файлов, шапка) | Уже отошли: свои имена и заголовки, чтобы отчёты не путались с FRST. |

## Чего у нас уже больше, чем у FRST

- **Карантин вместо удаления**: файлы и ветки реестра сохраняются в `Backups/`,
  а не исчезают безвозвратно.
- **Журнал исправления** с построчным статусом и итогом.
- **Точка восстановления** перед изменениями (если включено восстановление).
- **Портативность**: настройки и отчёты рядом с программой, без реестра и AppData.
- **Проверка каталожных подписей** (FRST тоже это умеет, но у нас прозрачно видно,
  что подпись каталожная).

## Предлагаемый порядок работ

1. Файлы в корне дисков и SvcHost — самые дешёвые из оставшихся.
2. Codecs, Safe Mode, Association-нюансы (UserChoice по всем пользователям).
3. Опциональный «один месяц» с фильтрами по папкам.
4. По запросу — вкладка поиска (файлы/реестр) и RE-режим.
