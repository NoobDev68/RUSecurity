# Context for AI Agents

## Overview

Проект — генератор fixlist для Farbar Recovery Scan Tool (FRST). Основной скрипт:
`GenFix.py` (v3). Вспомогательные: `frst_parser.py`, `detection_config.json` (пустой —
правила живут в коде), `rules.json` (статистика по корпусу, рантаймом не используется).
Тесты: `tests/test_detectors.py` и `tests/test_parser_and_output.py` (157 тестов, pytest).

Рабочая версия только `GenFix.py`; устаревшие копии (`generate_fixlist.py`, `2/`,
`*.bak`) удалены при чистке проекта (архив — `Generate_Fixlist_cleanup_20261119.zip`
рядом с папкой проекта).

## Core Flow

Запуск для пользователя: двойной клик по `Запустить GenFix.bat` (меню; GenFix
работает без прав администратора, консоль не меняется). Из консоли: `python GenFix.py`.

Пункт `0` завершает GenFix с кодом 0 — батник без `pause` закрывает окно терминала.
Окно FRST автоматически не закрывается (его запускает UAC-elevated процесс, а GenFix
не elevated); после выхода FRST при необходимости закрывается вручную.

1. **Scan** (`menu_scan`): удаляет старые отчёты и `fixlist.txt`, запускает
   `FRST64.exe` с правами администратора, ждёт маркеры конца в `FRST.txt` и
   `Addition.txt` (единый лимит `SCAN_TIMEOUT`, Ctrl+C прерывает в меню); без обоих
   готовых отчётов анализ не запускается.
2. **Analyse** (`menu_analyse`): берёт готовый `FRST.txt`, парсит FRST + Addition,
   детектит подозрительные записи, генерирует `FRST/fixlist.txt` в формате FRST.
   Если автодействий нет — fixlist не создаётся, только сообщение в логе.
3. **Apply** (`apply_fixlist`): копирует fixlist в папку FRST, удаляет старый
   `Fixlog.txt`, запускает FRST; пользователь нажимает «Fix», программа ждёт `Fixlog.txt`.
   Применение (все или выбранное) требует подтверждения `y/N`.
4. **Cleanup** (`menu_cleanup`): удаляет `FRST.txt`/`Addition.txt`/`fixlist.txt`
   только если они есть; при пустой папке сообщает «удалять нечего» и не спрашивает
   подтверждение.

## Key Architecture

- **Logging**: `log = logging.getLogger('generate_fixlist')`, `setup_logging(verbose)`
  пишет в `stderr`, чтобы CLI-вывод fixlist в `stdout` был чистым. `_init_console()`
  включает UTF-8 (CP 65001), ANSI VT и принудительно ставит TrueType-шрифт
  (`Consolas`), если conhost выбрал растровый `Terminal`. `resize_console()` вызывается
  **до** `_init_console`, а PowerShell-подпроцессы запускаются с `CREATE_NO_WINDOW`:
  иначе они сбрасывают кодовую страницу и в классическом conhost меню превращается
  в мусор.
- **Config**: `load_config()` читает `detection_config.json`; списки объединяются с
  хардкодными defaults (конфиг может добавлять правила, но не отменять базовые).
  Файл сейчас пустой — все правила живут в коде.
- **Parsing**: `parse_frst_report()` / `parse_additional_report()` понимают русские и
  английские заголовки секций и маркеры (`ВНИМАНИЕ`/`ATTENTION`, `Нет файла`/`No File`,
  `Файл не подписан`/`File not signed`). Кодировки: UTF-8, UTF-8 BOM, UTF-16, CP1251;
  `detect_encoding()` читает только префикс (64 КБ). Флаг `has_x_marker` — маркер `[X]`.
  Функции `parse_fixlist`, `match_action_to_entry`, `generalize_pattern`,
  `is_boilerplate_action`, `normalize_action_for_matching` — только для research
  (помечены баннером), рантайм их не вызывает.
- **Normalization**: `normalize_line()` из `frst_parser`.

## Detection Engine (`generate_fixlist`)

Порядок проверок:
0. Skip: Chrome components, legit extensions, Edge builtins, benign policies, known harmless,
   локальные DNS/прокси (`127.0.0.1`, `localhost`, `ManualProxies`) — только в комментарии
   для ручной проверки.
1. Always-fix: GroupPolicy/Policies с restriction, пустые Run с `[X]`, `Run: ... => [X]`,
   MountPoints2, Run keys с отсутствующим файлом, `SettingsPageVisibility`.
2. Malicious: известные extension IDs, browser hijack по malicious-доменам, FF plugin
   orphans (включая `FF Plugin HKU...`), Chrome push adware (suspicious TLD), dead tasks/
   Microsoft tasks с `(Нет файла)`, tasks без пути, tasks с GUID-only, CustomCLSID/
   ContextMenuHandlers/BHO/overlay без файла, `DcomLaunch ... отсутствует путь к файлу`.
3. Suspicious: unsigned/missing drivers, ShortcutTarget без файла, Shortcut без цели
   в Downloads/Temp/AppData, `U4 ... отсутствует ImagePath`.
4. Firewall rules — портовые правила без программы и осиротевшие правила в
   `Temp`/`Downloads`/`AppData`/с испорченным путём. Обычные осиротевшие правила
   программ не удаляются: это необязательная чистка.
5. Alternate Data Streams (кроме `Zone.Identifier` и `:encryptable`).
6. Расширения с adware-именами.
7. Подозрительные задачи.
8. Подозрительные пути.
9. Hidden programs.
10. Services/drivers с отсутствующим файлом.
11. Caution-marked entries (catch-all). Неизвестные расширения с одной лишь
    меткой «ВНИМАНИЕ» не трогаются; легитимные политики — только если нет
    restriction/ATTENTION.

Из hosts удаляются только подозрительные записи (malicious-домен или блокировка
google/microsoft/антивирусных доменов), остальные строки сохраняются; запись
hosts попадает в карантин (`kind: hosts`) и восстанавливается со страницы
«Карантин». Мёртвые overlay-записи удаляются по файлу,
а не «оптом». После детекции: FLock → extra paths, сортировка по числовому рангу
секций, сборка fixlist (UTF-8, CRLF, без метки `Код:`). `EmptyTemp:` добавляется
только для браузерных исправлений и удаления файлов из Temp, `Reboot:` — только
для служб/драйверов (кроме мёртвых записей без файла) и файлов драйверов.

Мёртвые служебные записи: отключённый AV/FW в Центре безопасности, которого нет
в списке установленных программ; `MSCONFIG\Services` о службе, отсутствующей в
отчёте; `CHR ...\Chrome\Extensions` без Path/update_url; битый ярлык в меню
«Пуск» на `C:\Program Files*`.

Важно: экспертные fixlist — шумные метки. В них есть ремонт (`sfc`, `ipconfig`,
`bitsadmin`), ручные удаления файлов, сброс DNS/прокси и даже удаление легитимных
расширений («Госплагин», Adobe). Это не переносится в универсальные правила;
`compare_all.py` считает «ядро» отдельно от ремонта и контекстной чистки.

## FRST Execution

- `_shell_execute(...)`: `ShellExecuteExW` с `SEE_MASK_NOCLOSEPROCESS |
  SEE_MASK_FLAG_NO_UI`; `verb='runas'` для UAC, ожидание через `WaitForSingleObject`.
  Без PowerShell-обёртки и проблем с кавычками.
- `_run_elevated(...)`: обёртка с `verb='runas'`.
- `wait_for_report`: ждёт стабильность размера 10 сек и точный маркер конца
  (`Конец от FRST.txt`, `Конец  Addition.txt`, `End of ...`); таймаут не считается
  успехом. Ожидание FRST.txt + Addition.txt ограничено единым `SCAN_TIMEOUT` (1800 сек).
- `_find_frst_exe()`: поиск `FRST64.exe` → `FRST.exe`; `_confirm_apply()` — подтверждение
  `y/N` перед запуском FRST на применение.
- `_read_last_line` / `_read_last_nonempty_line`: корректно работают с файлом без
  завершающего перевода строки и с пустыми строками в конце.
- `check_third_party_av()`: результат мемоизируется в `_av_cache` на процесс.

## Known Issues

1. FRST64.exe может блокироваться SmartScreen/антивирусом; при отказе UAC запуск
   возвращает `False` и пишет ошибку.
2. На очень медленных системах ожидание может упереться в `SCAN_TIMEOUT` (1800 сек
   на FRST.txt + Addition.txt, 600 сек на Fixlog); таймаут означает отказ от анализа,
   а не частичный fixlist.
3. `apply_fixlist` ждёт, пока пользователь нажмёт «Fix» в окне FRST.
4. Детекция эвристическая: возможны ложные срабатывания, особенно на нестандартных
   путях и самописных службах. Перед применением fixlist нужно просматривать.
5. `rules.json` и `extract_rules.py` — исследовательские артефакты, в рантайме не нужны.
6. `cleanup_frst_files` не удаляет `Fixlog.txt` (его полезно сохранить).
7. Окно FRST после выхода GenFix остаётся открытым — закройте его вручную.

## Constraints

- Python 3.11+, только stdlib + pytest.
- snake_case, typing аннотации; `normalize_line()` перед проверками.
- `log` для логирования, `print` для пользовательского ввода/вывода.
- Путь к FRST: `SCRIPT_DIR / 'FRST'`.
- Не добавлять комментарии без необходимости.

## RUSecurity (GUI-аналог FRST)

Пакет `rusecurity/` — портативное приложение: свой сканер пишет
`rusecurity-report.txt` и `rusecurity-add.txt` в формате, совместимом с
FRST (`core/scanner.py` + `core/sections/`), затем GUI сразу прогоняет их через
`GenFix.generate_fixlist` (`analyzer.py`), показывает найденные элементы списком
с галочками и исправляет выбранное своим фиксером.
Имена заданы в `rusecurity/names.py`; анализатор принимает и `FRST.txt` +
`Addition.txt`. Интерфейс — PySide6 из `.runtime/` (в git не входит), точка входа
`python -m rusecurity`; лаунчер `Запустить RUSecurity.bat`.

- Ассеты окна: `assets/rusecurity-logo.png` (логотип в сайдбаре, 2x) и
  `assets/RUSecurity.ico` (иконка окна и exe, 16–256 px). В сборке пути берутся
  через `config.resource_path()`, поэтому exe собирается с
  `--add-data "assets;assets"`; без этого в сайдбаре остаётся текст «RUSecurity».
- `core/scanner.py` — `ScanOptions` (все разделы включены по умолчанию) и списки
  `REPORT_OPTIONS`/`ADDITION_OPTIONS`; отключённые разделы не собираются, а если
  выключен весь доп. отчёт, старые `rusecurity-add.txt`/`Addition.txt` удаляются,
  чтобы не попасть в анализ.
- `ui/pages.py` — страница «Сканирование» из двух экранов: настройки (галочки
  разделов, кнопка «Сканировать», широкий прогресс-бар с текущим разделом) и
  «Найденные элементы» (таблица с чекбоксами, директивы
  `CreateRestorePoint`/`CloseProcesses`/`EmptyTemp`/`Reboot`, кнопки
  «Рекомендовано» — отмечает всё найденное и ставит директивы из анализа — и
  «Исправить»). Экран результатов открывается после каждого скана, даже если
  элементов 0 (тогда показывает карточку «Подозрительных элементов не найдено»);
  «Изменить разделы» возвращает к настройкам. Колонка «Элемент» переносит текст
  по словам и строкам (длинные пути видны целиком), полный текст — и в подсказке.
  Страница «Журнал» — подробный лог,
  он же пишется в `Reports/rusecurity-journal.txt` (`rusecurity/journal.py`).
  Сверху — блок «Откат исправлений»: `restore.load_runs()` перечисляет
  `Reports/Backups/*/manifest.json` (новые сверху), `restore.run_entries(run)`
  отдаёт все записи одного исправления, откат идёт через `RestoreWorker` и
  `restore.restore_many` — файлы возвращаются, ветки реестра импортируются,
  hosts перезаписывается. Список обновляется при показе страницы и кнопкой
  «Обновить».
- `ui/workers.py` — `ScanWorker` (скан + анализ + время), `FixWorker` (фиксер,
  при нехватке прав — UAC-перезапуск), `RestoreWorker`.
- `analyzer.py` — `findings()` (категория, вид действия, признак «только вручную»),
  `directives()`, `compose_fixlist()`; `Finding`/`AnalysisResult` для GUI.
- `core/winapi.py` — winreg, Authenticode + каталожная подпись, разбор `.lnk`
  через COM, процессы; всё на ctypes/stdlib.
- `fixer/` — свой исполнитель fixlist вместо FRST: `actions.py` разбирает строки
  в действия, `execute.py` делает бэкапы (`.reg`-экспорт, карантин файлов),
  точку восстановления, манифест и журнал, `restore.py` возвращает объекты из
  карантина (и удаляет выбранные/все записи), `elevate.py` поднимает UAC.
  `schedule_reboot()` планирует `shutdown /r /t 30`; GUI после исправления с
  `reboot_required` спрашивает «перезагрузить сейчас / позже», сам фиксер в GUI
  перезагрузку не запускает (CLI `apply --reboot` — по-прежнему сразу).
  CLI — `apply` и `restore`, GUI — кнопка «Исправить» и страница «Карантин».
  Неподдерживаемые строки — `manual`.
  Директива `CloseProcesses:` закрывает процессы, чьи файлы выбраны к удалению
  (`winapi.list_processes` + `terminate_process`).
  `Reg: reg add` дополнительно пишется в манифест как `reg_new` (значение для
  удаления при откате): без этого исправление, создавшее новый ключ, нельзя
  вернуть — `reg export` несуществующего ключа ничего не сохраняет.
- `fixer/browsers.py` — автоисправление браузерных настроек: строки
  `CHR/Edge/Brave/YAN/OPR DefaultSearchURL|DefaultSearchKeyword|HomePage|StartupUrls`
  и `FF Homepage`. Браузер закрывается (`close`), затем правятся
  `Preferences`/`Secure Preferences` (удаляются ключи провайдера/домашней
  страницы и их MAC в `protection.macs`) или `prefs.js` (домашняя страница →
  `about:home`). Перед правкой файл копируется в бэкап как `file_edit`, откат
  возвращает копию поверх изменённого файла. Для Chromium это сброс выбора на
  встроенную поисковую систему; удалить сам движок из списка (`Web Data`) не
  пытаемся. Профиль ищется по метке из отчёта (`Default`, имя профиля FF).
- `fixer/extensions.py` — строки `CHR/Edge/Brave/YAN Extension:`: удаляет запись
  расширения из `Preferences` и его папку (в карантин). Запись, которая
  дублируется в `Secure Preferences` (защищённые настройки с HMAC), не правится —
  иначе Chrome сбросит весь список расширений; такая запись исчезнет при
  следующем запуске браузера, папка удаляется сразу. Сканер пишет в строке
  настоящий путь расширения из `settings.path`, а не `Extensions\<id>`, поэтому
  мёртвая запись без папки всё равно находится и удаляется.
- Сканер дополнительно собирает `SigCheck` (MD5 и подпись контрольных системных
  файлов), `BCD` (bcdedit, только чтение), `Ассоциация` (класс и команда для
  `.exe/.bat/.reg/...`), `Alternate Data Streams` (обход Temp/Downloads/ProgramData),
  точки восстановления и ошибки журнала событий. exe собирается с манифестом
  `requireAdministrator`, поэтому GUI всегда работает от администратора и
  показывает фактический уровень прав.
- `core/delta.py` — снимки сканов в `Reports/history` и сравнение «новые/исчезли»;
  в сканере `history=True`, в CLI флаги `--delta` и `--no-history` (в GUI не
  показывается).
- `_needs_empty_temp` в GenFix не реагирует на ADS (`14_ads`): удаление потока
  само по себе не требует очистки Temp.
- Формат строк сверен с корпусом `Parse_FRST_SafeZone/pairs`; REA-доказательства
  по FRST64.exe — `docs/rea/REA_EVIDENCE.md`; что брать из FRST дальше —
  `docs/RECOMMENDATIONS.md`.
- Отдельный Shortcut.txt не формируется: ярлыки идут в раздел «Ярлыки & WMI»
  доп. отчёта, `format_shortcut` ставит `(Нет файла)` для мёртвой цели, а сломанные
  ярлыки попадают в общий список найденного (удаление — через фиксер, в карантин).
- Тесты формата и связки сканер→анализ — `tests/test_rusecurity.py`.

### Проверка безопасности (hardening)

Отдельная функция, не связанная с FRST-сканированием: сверяет известный набор
параметров Windows с рекомендуемыми значениями и исправляет отклонения.
Ядро — `rusecurity/core/hardening.py` (`RULES`, `evaluate()`,
`compose_fixlist()`); страница — `ui/hardening_page.py` (таблица с галочками,
кнопки «Проверить»/«Рекомендовано»/«Отметить всё»/«Исправить», описание
выбранной проверки под таблицей); CLI — `rusecurity hardening`
(`--fix`, `--dry-run`, `--verbose`).

- До запуска страница не пустая: `hardening.rule_preview()` отдаёт все правила
  с прочерком вместо текущего значения, поэтому виден полный список проверок,
  а клик по строке показывает описание ещё до проверки. После проверки таблица
  заполняется только найденными отклонениями.
- Правило (`Rule`) описывает одно значение реестра: путь, имя, ожидаемое
  значение (`op` + `expected`), значение для исправления и признак
  `missing` — считается ли отклонением отсутствие значения.
  `missing='bad'` ставится только там, где отсутствие означает
  незащищённое состояние Windows по умолчанию.
- Признак `recommended` задаёт набор «Рекомендовано»: важные исправления без
  побочных эффектов. Вне набора — подпись SMB (старые NAS), LLMNR
  (обнаружение устройств), стенограмма PowerShell (место на диске) и
  проверки, которые вообще не исправляются автоматически (включённый RDP,
  исходящий NTLM, сервер обновлений). Обычное исключение Defender тоже
  необязательно: удаляется вручную при желании.
- Клик по строке показывает под таблицей описание проверки: раздел, важность,
  текущее и рекомендуемое значение, пользу («Почему исправлять»), возможные
  минусы («Возможные минусы»), напоминание об обратимости и статус
  («рекомендуется», «необязательная», «только вручную»). У каждого правила
  заполнены `note` и `risk` — тест `test_every_rule_explains_reason_and_risk`
  не даёт оставить проверку без объяснения.
- У проверок без автолечения (`fix_value` пуст) заполнены `how_to` (путь в
  интерфейсе Windows) и `command` (команда PowerShell): карточка показывает их
  как «Как исправить» и «Команда PowerShell», команда выделяется мышью.
  Инструкцию требует тест `test_manual_rules_explain_how_to_fix`.
- Покрыто то, чего нет в детекторах GenFix: LSA/NTLM и WDigest, RDP (NLA,
  TLS, шифрование), SMB1/гостевой вход/подпись, LLMNR, три профиля
  брандмауэра, журналирование PowerShell, размер журнала Security и служба
  журналов, автообновление, исключения Defender. UAC, SmartScreen и
  отключение Defender не дублируются — их разбирает анализ отчёта.
- Исправление выполняется штатным фиксером: fixlist собирается из строк
  `Reg: reg add ...`, поэтому работают бэкап ветки, точка восстановления,
  журнал и обратимость. Директива `Reboot:` добавляется автоматически, если
